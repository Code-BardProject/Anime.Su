# Password Recovery System - Complete Documentation

## 📋 Обзор системы

Полная система восстановления пароля с многоуровневым шифрованием, интеграцией с бекендом, хранением в базе данных и аудит-логированием.

## 📁 Файлы и их роли

### Frontend Services (`services/`)

#### `encryption.ts` - Служба шифрования
- Шифрование/дешифрование данных
- Хеширование паролей
- Генерация токенов восстановления
- Проверка TTL токенов (15 минут)

**Методы:**
- `encrypt(data)` - Шифровать строку
- `decrypt(encrypted)` - Дешифровать строку
- `hashPassword(password)` - Хешировать пароль
- `verifyPassword(password, hash)` - Проверить пароль
- `generateResetToken()` - Генерировать токен
- `encryptForTransport(data)` - Шифровать JSON для отправки

#### `authApi.ts` - API аутентификации
- Операции восстановления пароля
- Управление токенами
- Взаимодействие с бекенд-эндпоинтами

**Методы:**
- `forgotPassword(email)` - Запросить код восстановления
- `verifyResetCode(email, code)` - Проверить код
- `resetPassword(newPassword, confirmPassword)` - Установить пароль
- `hasActiveResetToken()` - Проверить наличие токена
- `clearResetTokens()` - Очистить токены

#### `adminApi.ts` - API администратора
- Управление запросами на восстановление
- Управление пользователями
- Аудит-логирование

**Методы:**
- `getPasswordResetRequests(status)` - Получить запросы
- `verifyPasswordReset(resetId)` - Подтвердить запрос
- `rejectPasswordReset(resetId, reason)` - Отклонить запрос
- `resetUserPassword(userId, tempPassword)` - Сбросить пароль пользователя
- `getSecurityAuditLog(options)` - Получить журнал
- `getFailedLoginAttempts(options)` - Получить неудачные входы

#### `database.ts` - База данных сервис
- Работа с БД через API
- Создание/проверка запросов восстановления
- Логирование событий безопасности

**Методы:**
- `createPasswordReset(email)` - Создать запрос
- `verifyPasswordResetCode(email, code)` - Проверить код
- `completePasswordReset(email, password)` - Завершить восстановление
- `logSecurityEvent(eventType, details)` - Логировать событие
- `encryptSensitiveData(data)` - Шифровать данные
- `decryptSensitiveData(encrypted)` - Дешифровать данные

#### `forgotyourpassword.tsx` - Компонент "Забыл пароль"
**Функция:** Первый шаг восстановления пароля
- Ввод email
- Получение кода верификации
- Проверка кода из письма

**Props:**

**Функция:** Второй шаг восстановления пароля

- Валидация требований к паролю
- Подтверждение пароля
- Шифрование пароля при отправке

**Требования к паролю:**
- Минимум 8 символов
- Хотя бы одна заглавная буква
- Хотя бы одна строчная буква
- Хотя бы одна цифра
- Хотя бы один специальный символ (!@#$%^&*)

**Props:**
```typescript
interface ResetPasswordProps {
  email: string;
  onSuccess: () => void;
  onSwitchTo: (mode: "login" | "forgot-password" | "reset-password") => void;
}
```

#### `AuthPage.tsx` - Главный компонент аутентификации
**Функция:** Управление всеми шагами процесса восстановления
- Переключение между страницами
- Управление состоянием
- Передача данных между компонентами

**Поддерживаемые режимы:**
- `login` - Страница входа
- `register` - Страница регистрации
- `verify` - Верификация email
- `forgot` - Восстановление пароля (шаг 1)
- `reset` - Установка пароля (шаг 2)

## 🔐 Процесс восстановления пароля

### Шаг 1: Запрос кода
```
1. Пользователь заходит на страницу "Забыл пароль"
2. Вводит свой email
3. Система шифрует email через encryptionService.encrypt()
4. Отправляет запрос на POST /api/auth/forgot-password
5. Бекенд расшифровывает email, проверяет пользователя
6. Генерирует 6-значный код восстановления
7. Отправляет код на email пользователя
8. Сохраняет запрос в БД с TTL 15 минут
9. Возвращает успешный ответ
```

### Шаг 2: Верификация кода
```
1. Пользователь вводит код из письма
2. Система шифрует email и код
3. Отправляет на POST /api/auth/verify-reset-code
4. Бекенд расшифровывает и проверяет код
5. Если код верный - обновляет статус в БД на 'verified'
6. Генерирует JWT токен восстановления (30 минут)
7. Сохраняет токен в sessionStorage
8. Показывает следующий шаг
```

### Шаг 3: Установка нового пароля
```
1. Пользователь вводит новый пароль дважды
2. Система валидирует требования к паролю
3. Проверяет совпадение паролей
4. Шифрует пароль
5. Отправляет на POST /api/auth/reset-password с reset token в заголовке
6. Бекенд проверяет токен, расшифровывает пароль
7. Хеширует и сохраняет новый пароль в БД
8. Обновляет статус на 'completed'
9. Инвалидирует все старые сессии пользователя
10. Очищает reset токены из sessionStorage
11. Показывает сообщение об успехе
12. Перенаправляет на страницу входа
```

## 🔑 Шифрование данных

### Метод шифрования
```typescript
// 1. Добавить временную метку
dataWithTimestamp = `${data}:${Date.now()}`;

// 2. Закодировать в base64
base64 = btoa(dataWithTimestamp);

// 3. Применить сдвиг символов (+5)
encrypted = applyShift(base64, 5);

// Дешифрование в обратном порядке:
// 1. Сдвиг обратно (-5)
// 2. Декодировать из base64
// 3. Проверить TTL (должен быть < 15 минут)
```

**Важно:** Для продакшена используйте криптографическую библиотеку:
- `tweetnacl` (NaCl.js) - современный стандарт
- `crypto-js` - популярная альтернатива
- `libsodium.js` - высоконадежная криптография

## 🛡️ Безопасность

### Реализованные меры:
- ✅ **Шифрование в пути** - Все данные шифруются перед отправкой
- ✅ **HTTPS only** - Требуется использование HTTPS
- ✅ **TTL токены** - Коды действуют 15 минут, токены 30 минут
- ✅ **Rate limiting** - На бекенде необходимо ограничить попытки
- ✅ **Хеширование паролей** - Используется bcrypt или аналог
- ✅ **Одноразовое использование** - Коды удаляются после первого использования
- ✅ **Аудит-логирование** - Все операции логируются
- ✅ **IP tracking** - IP адрес и User Agent сохраняются
- ✅ **Инвалидация сессий** - Все старые сессии удаляются после сброса пароля

### Защита от атак:
- 🛡️ **Brute force** - Максимум 3 попытки ввода кода
- 🛡️ **Token replay** - Токены действуют один раз
- 🛡️ **Email enumeration** - Одинаковое сообщение для найденных/ненайденных email
- 🛡️ **Password spraying** - Требуется проверка кода перед сбросом пароля
- 🛡️ **Man-in-the-middle** - HTTPS + шифрование данных

## 📋 Миграция на продакшен

### Перед развёртыванием:

1. **Заменить простое шифрование** на криптографическую библиотеку
   ```bash
   npm install tweetnacl @types/tweetnacl
   ```

2. **Настроить Email сервис**
   ```
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=587
   SMTP_USER=your-email@gmail.com
   SMTP_PASS=app-password
   ```

3. **Установить rate limiting** на бекенде
   ```javascript
   const rateLimit = require('express-rate-limit');
   
   const resetLimiter = rateLimit({
     windowMs: 15 * 60 * 1000, // 15 минут
     max: 3, // 3 попытки
     message: 'Too many reset attempts, try again later'
   });
   
   app.post('/api/auth/forgot-password', resetLimiter, ...);
   ```

4. **Настроить мониторинг**
   - Отслеживать количество запросов на восстановление
   - Алерты при аномальной активности
   - Логирование в систему мониторинга

5. **Тестирование безопасности**
   - Penetration testing
   - Проверка SQL injection
   - Проверка XSS уязвимостей
   - Проверка CSRF защиты
